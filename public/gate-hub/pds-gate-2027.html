1. C Programming Fundamentals

Types, operators, evaluation rules and the preprocessor — the facts that decide what a GATE "what does this program print?" question outputs. For questions in this section, assume 32-bit int and 64-bit pointers (8 bytes) unless stated otherwise.
Scope of this assumption
These sizes are a convention for the examples and practice questions in this hub, not a property of C. The C standard only guarantees sizeof(char) == 1, minimum value ranges (int ≥ 16 bits, long ≥ 32 bits, long long ≥ 64 bits) and the ordering short ≤ int ≤ long ≤ long long. In a real GATE question, use the machine assumptions the question gives (e.g. “4-byte int”, “8-byte pointers”) and do not carry the numbers below into other problems.

Data types and sizes

Unsigned arithmetic wraps modulo 2n. Signed overflow is undefined behaviour. In mixed signed/unsigned expressions the signed operand is converted to unsigned.

Operators, precedence and evaluation

  • Integer division truncates toward zero (C99): 7/2 = 3, -7/2 = -3, 7/-2 = -3. The remainder takes the sign of the dividend: -7 % 2 = -1. Always (a/b)*b + a%b == a.
  • Precedence (high → low, simplified): () [] -> . → unary ! ~ ++ -- * & sizeof → * / % → + - → << >> → < <= > >= → == != → & → ^ → | → && → || → ?: → assignment → ,.
  • Relational operators are left-associative and yield 0 or 1, so 5 > 3 > 1 is (5 > 3) > 1 = 1 > 1 = 0.
  • Short-circuit: in a && b b is evaluated only if a is true; in a || b only if a is false. So if (i++ && j++) with i = 0, j = 0 leaves i = 1, j = 0.
  • Prefix ++i increments then yields the new value; postfix i++ yields the old value then increments.
  • Undefined behaviour
    Modifying a variable twice between sequence points — i = i++ + ++i, a[i] = i++, printf("%d %d", i++, i) — is undefined or unspecified. GATE usually avoids it; if an option says "undefined/compiler dependent", it is often right.
Worked numerical — integer and unsigned semantics
unsigned char c = 200;
c = c + 100;                   // 300 mod 256 = 44                     → prints 44
printf("%d", -1 < 1u);          // -1 converted to unsigned = 4294967295 → comparison false → 0
printf("%d", -7/2 + -7%2);     // -3 + (-1) = -4
Output of the three prints: 44, 0, −4 (verified by compiling and running).
Worked numerical — switch fall-through and loops
int k = 3;
switch (k) { case 1: printf("one ");  case 3: printf("three ");  case 4: printf("four "); break;  default: printf("def "); }
// prints:  three four       (no break after case 3, so execution falls into case 4)

for (i = 0; i < 5; i++) { if (i == 2) continue; if (i == 4) break; s += i; }
// s = 0 + 1 + 3 = 4, and i ends at 4

The preprocessor

Macros are textual substitution before compilation — no type checking, no evaluation of arguments. Always parenthesise arguments and the whole body.

Worked numerical — macro pitfalls

2. Pointers, Arrays, Strings & Memory

A pointer is an address; arrays and pointers are tightly linked; structures are padded for alignment; and malloc/free put memory management in your hands. Size-dependent examples here assume 32-bit int and 64-bit pointers unless stated otherwise.

Pointer arithmetic

  • For T *p, p + k advances by k · sizeof(T) bytes. p - q (same array) gives the number of elements between them, not bytes.
  • a[i] is defined as *(a + i), so i[a] works too: for int arr[] = {1,2,3,4}, 2[arr] = 3.
  • The array name decays to a pointer to its first element in most expressions — but sizeof(a) gives the whole array (20 bytes for int a[5]), while for a function parameter int a[] is really int *a, so sizeof(a) there is 8.
  • An array name is not an lvalue: a = p; is illegal, a++ is illegal.
Pre/postfix with pointers
*p++    value at p, then p moves  (postfix binds tighter than *)
(*p)++  increments the VALUE
*++p    moves p first, then reads
++*p    increments the value, yields new value
Dereference and address
int x = 5, *p = &x, **pp = &p;
*p = 7;     // x is 7
**pp = 9;   // x is 9
*(&x) == x
Worked numerical — traversing with a pointer
int a[] = {10, 20, 30, 40, 50};  int *p = a;
int v1 = *p++;     // v1 = 10, p now points to a[1]
int v2 = *p;       // v2 = 20
int v3 = ++*p;     // a[1] becomes 21, v3 = 21
// p - a = 1, and a[1] is now 21         → v1, v2, v3 = 10, 20, 21

Two-dimensional arrays

C stores 2-D arrays in row-major order. For int m[R][C]: &m[i][j] = base + (i·C + j)·sizeof(int), and m[i][j] == *(*(m + i) + j). Here m + 1 advances a whole row (C elements), whereas *m + 1 advances one element.

Worked numerical
int m[3][4]: &m[2][1] − &m[0][0] = 2·4 + 1 = 9 elements. sizeof(m) = 48, and sizeof(m)/sizeof(m[0]) = 3 rows.

Call by value and pointers

C passes everything by value. A function receives a copy, so swapping two ints requires passing their addresses:

void swapv(int a, int b) { int t = a; a = b; b = t; }      // swaps the copies only
void swapp(int *a, int *b) { int t = *a; *a = *b; *b = t; } // swaps the caller's variables
// u = 3, w = 4:  swapv(u, w) → still 3 4;   swapp(&u, &w) → now 4 3

Strings

  • A string is a char array ending with '\0'. strlen does not count the terminator, sizeof of an array does.
  • char s[] = "GATE"; → a writable array: sizeof(s) = 5, strlen(s) = 4. char *t = "GATE"; → a pointer to a read-only literal: sizeof(t) = 8, and modifying t[0] is undefined behaviour.
  • Comparing strings with == compares addresses; use strcmp. strcpy needs a destination of at least strlen+1 bytes.

Structures, unions and padding

Each member is aligned to its own size; the whole struct is padded to a multiple of its largest alignment. Member order matters. A union shares one block of memory; its size is the largest member, rounded up to the alignment.

Worked numerical — sizeof with padding (verified with gcc)
struct A { char c; int i; char d; };        c(1) + pad(3) + i(4) + d(1) + pad(3)   = 12
struct B { int i; char c; char d; };        i(4) + c(1) + d(1) + pad(2)            = 8
struct C { char c; double d; int i; };      c(1) + pad(7) + d(8) + i(4) + pad(4)   = 24
union  U { int i; char c[6]; };             max(4, 6) = 6, rounded to alignment 4   = 8
Reordering members from largest to smallest alignment usually minimises padding.

Dynamic memory

FunctionBehaviour
malloc(n)n uninitialised bytes from the heap; NULL on failure
calloc(k, n)k·n bytes, zero-initialised
realloc(p, n)resize; may move the block (old pointer becomes invalid)
free(p)returns the block; free(NULL) is safe; freeing twice is undefined
  • Memory leak: allocated memory that is no longer reachable and never freed.
  • Dangling pointer: pointer to memory that was freed, or to a local variable that has gone out of scope (returning &local from a function).
  • Wild/uninitialised pointer: never assigned; dereferencing it is undefined. Set pointers to NULL after free.
  • Memory layout: code (text), static/global data, heap (grows up), stack (grows down).

Function pointers

int (*op)(int, int) = add;   // pointer to a function returning int taking two ints
int r = op(2, 3);            // calls add(2, 3);   used for callbacks, qsort's comparator

3. Functions & Recursion

How calls use the stack, how to trace recursive programs by hand, and how to count calls and stack depth.

How a call works

Each call pushes an activation record (stack frame) holding the parameters, the return address, saved registers and local variables; return pops it. Recursion works because every invocation has its own frame. Stack depth = number of active (not yet returned) calls — infinite recursion ends in stack overflow.

  • Parameters are passed by value (copies). Locals are re-created on every call; static locals and globals are shared across all invocations.
  • The order in which operands of +, function arguments, etc. are evaluated is unspecified in C — avoid questions that depend on it (for example, an expression that reads a global that a recursive call in the same expression modifies).
  • Tail recursion: the recursive call is the very last action (return f(n-1, acc*n);); a compiler can reuse the frame, turning it into a loop with O(1) stack. return n * f(n-1); is not tail recursive (a multiplication follows the call).

Tracing technique

  1. Write the call tree. Mark what is printed before the recursive calls (pre-order) and after them (post-order).
  2. Evaluate from the base case upward; keep local variables separate per call.
  3. For counting problems write a recurrence for the number of calls and solve it.
Worked numerical — print between two recursive calls
void ruler(int n) { if (n == 0) return;  ruler(n-1);  printf("%d ", n);  ruler(n-1); }
ruler(3):   ruler(2) prints  1 2 1;  then 3;  then ruler(2) prints 1 2 1
Output:  1 2 1 3 1 2 1

Calls: C(0) = 1,  C(n) = 2·C(n−1) + 1  →  C(n) = 2ⁿ⁺¹ − 1  →  C(3) = 15 calls
Number of values printed = 2ⁿ − 1 = 7

Classic recursive functions

Worked numerical — number of calls in naive Fibonacci
Let C(n) = calls made by fib(n): C(0) = C(1) = 1 and C(n) = C(n−1) + C(n−2) + 1. 
C(2) = 3   C(3) = 5   C(4) = 9   C(5) = 15   C(6) = 25
In general C(n) = 2·F(n+1) − 1.  fib(5) returns 5 and makes 15 calls (counted by running the program).
Many of these calls recompute the same value — the reason dynamic programming and memoisation turn the time into O(n).
GATE angle
Three things to check every time: (1) what is printed before vs after the recursive call; (2) static / global state shared across calls; (3) the base case — a missing or unreachable base case means infinite recursion. Also be ready to give the space complexity as the maximum depth of the recursion, not the number of calls.

4. Arrays, Stacks & Queues

Linear data structures with strict access rules: LIFO stacks, FIFO queues, and the expression evaluation problems built on them.

Arrays

OperationUnsorted arraySorted array
Access by indexO(1)O(1)
SearchO(n)O(log n) (binary search)
Insert / delete at a positionO(n) (shift elements); O(1) at the endO(n)

Address of element i of a 1-D array = base + (i − lower)·w; 2-D addressing is as in the pointer section. Sparse matrices are stored as triples (row, col, value) or in CSR form to save space.

Stack (LIFO)

Operations push, pop, peek, isEmpty all take O(1). Uses: function calls, undo, expression evaluation, balanced-bracket checking, DFS, backtracking.

  • Two stacks in one array of size n: start one at index 0 growing up, the other at n−1 growing down; overflow only when they meet — the whole array is usable.
  • Stack permutations: if 1, 2, …, n are pushed in order and popped at any time, the number of possible pop sequences is the Catalan number C(n) = (1/(n+1))·C(2n, n): n = 3 → 5 (only 3 1 2 is impossible), n = 4 → 14.

Infix → postfix with a stack

Scan left to right. Operands go straight to the output. For an operator, pop operators of higher or equal precedence (for left-associative operators; for the right-associative ^ only strictly higher) to the output, then push it. ( is pushed; ) pops until (. At the end pop everything.

Worked numerical — conversions
A + B * C - D / E        →  A B C * + D E / -          (max stack size 2)
A * (B + C) / D - E      →  A B C + * D / E -          (max stack size 3, counting the parenthesis)
(A + B) * (C - D)        →  A B + C D - *

Postfix evaluation

Operands are pushed; an operator pops two values (right operand first), applies the operation and pushes the result. The stack depth needed is the maximum number of pending operands.

Worked numerical
5 6 2 + * 12 4 / -: 
push 5, 6, 2     [5 6 2]
+                [5 8]
*                [40]
push 12, 4       [40 12 4]
/                [40 3]
-                [37]       → result 37   (maximum stack size 3)

Queue (FIFO)

Operations enqueue at the rear, dequeue from the front — O(1) with a linked list or a circular array. Uses: BFS, scheduling, buffering, level-order traversal.

  • Circular array queue of size n (indices mod n), with front = index of the first element and rear = index of the next free slot, one slot kept empty: 
    empty : front == rear
full  : (rear + 1) % n == front        → capacity n − 1
count : (rear − front + n) % n
    Without the "wasted slot" trick, front == rear is ambiguous between empty and full, so a separate counter is needed.
  • Queue using two stacks: push into stack 1; to dequeue, if stack 2 is empty move everything from stack 1 over (reversing order), then pop stack 2. Each element moves at most once → amortised O(1) per operation. A stack using two queues needs one operation to cost O(n).
  • Deque allows insertion/deletion at both ends; a priority queue removes the highest-priority element (implemented with a heap).
Worked numerical
Circular queue with n = 8, front = 5, rear = 2: count = (2 − 5 + 8) mod 8 = 5 elements (at indices 5, 6, 7, 0, 1).
Remember
BFS uses a queue; iterative DFS uses a stack (recursion uses the system call stack). Minimum number of stacks needed to simulate a queue = 2; minimum number of queues to simulate a stack = 2.

5. Linked Lists

Dynamic sequences built from nodes joined by pointers: cheap insertion and deletion, but no random access.

Node structure and types

struct node { int data;  struct node *next; };       // singly linked
struct dnode { int data; struct dnode *prev, *next; }; // doubly linked
  • Singly: traverse one way only. Doubly: both ways; can delete a given node in O(1). Circular: last node points back to the first (no NULL); the traversal condition is p->next != head.
  • Use a dummy (sentinel) head node to avoid special cases for the first element.
  • A list with n nodes holds n next pointers (singly) or 2n pointers (doubly), plus the head pointer.

Complexity

OperationSingly (head only)Singly (head + tail)Doubly
Insert at frontO(1)O(1)O(1)
Insert at endO(n)O(1)O(1) with tail
Delete firstO(1)O(1)O(1)
Delete lastO(n) (need predecessor)O(n)O(1) with tail
Delete a node given a pointer to itO(n) normally (O(1) trick below)–O(1)
Search / access k-thO(n) — binary search is not possible on a linked list in O(log n)

O(1) deletion trick (node is not the last): copy the next node's data into the given node, then unlink and free the next node.

Essential algorithms

Reverse a list (iterative, O(n) time, O(1) space)
prev = NULL; cur = head;
while (cur) {
  nxt = cur->next;
  cur->next = prev;
  prev = cur;  cur = nxt;
}
head = prev;
Performs exactly n pointer reversals.
Middle / cycle (two pointers)
slow = fast = head;
while (fast && fast->next) {
  slow = slow->next;
  fast = fast->next->next;   // meets slow iff a cycle exists
}
// no cycle: slow is the middle
Floyd's cycle detection: O(n) time, O(1) space.
  • k-th node from the end: advance one pointer k steps, then move both until the first hits NULL — one pass.
  • Merge two sorted lists: O(m + n) time, O(1) extra space. Merge sort on a linked list: O(n log n) time (and it is the preferred sort for lists). Insertion sort works on a list in O(n²).
  • Polynomial and large-integer arithmetic, adjacency lists and hash-chaining all rely on linked lists. An XOR linked list stores prev ⊕ next in one field to halve the pointer cost.
Worked numerical — recursion on a list
void fun(struct node *h) {
    if (!h) return;
    printf("%d ", h->data);
    if (h->next) fun(h->next->next);
    printf("%d ", h->data);
}
List: 1 → 2 → 3 → 4 → 5          fun(head) prints:  1 3 5 5 3 1
fun(1) prints 1, jumps to 3; fun(3) prints 3, jumps to 5; fun(5) prints 5, next is NULL so no call;
then each frame prints its value again on the way back: 5, 3, 1.
Worked numerical — delete alternate nodes
Keep a node, unlink its successor, move to the node after: on 1→2→3→4→5 the loop leaves 1→3→5; on 1→2→3→4→5→6 it also leaves 1→3→5.
Array vs linked list
Array: random access O(1), contiguous, cache-friendly, fixed or costly resize, insertion O(n). Linked list: insertion/deletion O(1) once the position is known, no resize cost, extra pointer memory per node, no random access.

6. Trees, BST & AVL

Hierarchical structures: counting formulas, traversals, binary search trees and self-balancing trees.

Binary tree facts

Take the root at level 0 and the height of a single node as 0 (height = number of edges on the longest root–leaf path). Be careful: some problems count levels from 1 — read the convention.

  • Maximum nodes at level i = 2i. Maximum nodes in a tree of height h = 2h+1 − 1 (h = 3 → 15). Minimum height of n nodes = ⌊log₂ n⌋.
  • A binary tree with n nodes has n − 1 edges and n + 1 NULL child pointers.
  • In any binary tree: (leaves) = (nodes with 2 children) + 1.
  • For a tree in which every internal node has exactly k children: with i internal nodes, n = k·i + 1 nodes and (k−1)·i + 1 leaves. With k = 3 and i = 10 → 21 leaves. A full binary tree with i internal nodes has i + 1 leaves.
  • Number of structurally different binary trees with n nodes = Catalan(n) = C(2n, n)/(n+1): 1, 2, 5, 14, 42 for n = 1…5. The same number of distinct BSTs can be built on n distinct keys: 4 keys → 14.
  • Complete tree in an array (0-based): children of i are 2i+1 and 2i+2, parent is ⌊(i−1)/2⌋ (1-based: 2i, 2i+1, ⌊i/2⌋).

Traversals

TraversalOrderTypical use
InorderLeft, Node, Rightsorted output of a BST
PreorderNode, Left, Rightcopy a tree; prefix expression
PostorderLeft, Right, Nodedelete a tree; postfix expression; evaluate expression trees
Level orderlevel by level (queue)BFS, shortest depth
  • All recursive traversals take O(n) time and O(h) stack space. Morris traversal does inorder in O(1) space using threads.
  • Unique reconstruction: inorder + preorder, or inorder + postorder, determine a binary tree uniquely. Preorder + postorder do not (unless every node has 0 or 2 children). The first preorder element (or last postorder element) is the root; split the inorder sequence around it.

Binary search tree (BST)

Left subtree keys < node < right subtree keys. Search, insert and delete cost O(h): O(log n) when balanced, O(n) when skewed (e.g. keys inserted in sorted order). The inorder traversal of a BST is sorted.

Deletion: (1) leaf → remove; (2) one child → replace by that child; (3) two children → replace the key by its inorder successor (minimum of the right subtree) or predecessor, then delete that node.

Worked numerical — build, traverse, delete
Insert 50, 30, 70, 20, 40, 60, 80, 35 into an empty BST. 
        50
      /    \
    30      70
   /  \    /  \
  20  40  60  80
      /
    35
Inorder  : 20 30 35 40 50 60 70 80        (sorted)
Preorder : 50 30 20 40 35 70 60 80
Postorder: 20 35 40 30 60 80 70 50        height = 3

   Preorder now: 50 35 20 40 70 60 80

   Preorder now: 60 35 20 40 70 80

AVL tree (height-balanced)

A BST in which the balance factor (height of left − height of right) of every node is −1, 0 or +1. After an insert or delete, rebalance with rotations at the lowest unbalanced node:

CaseCauseFix
LLinsertion into left subtree of left childone right rotation
RRinsertion into right subtree of right childone left rotation
LRinsertion into right subtree of left childleft rotation on the child, then right rotation
RLinsertion into left subtree of right childright rotation on the child, then left rotation
  • Height is always O(log n) (≤ 1.44 log₂ n), so search/insert/delete are O(log n). Insertion needs at most one (single or double) rotation; deletion may need O(log n) rotations.
  • Minimum nodes of an AVL tree of height h: N(h) = N(h−1) + N(h−2) + 1 with N(0) = 1, N(1) = 2: 1, 2, 4, 7, 12, 20, 33, 54 for h = 0…7. So height 4 needs at least 12 nodes.
Worked numerical — AVL insertions
Insert 10, 20, 30, 40, 50, 25: 
10, 20, 30   → right-right imbalance at 10         → left rotation          root 20 (10, 30)
40           → fits                                  
50           → right-right imbalance at 30         → left rotation          20 (10, 40(30, 50))
25           → under 30's left; imbalance at 20 is right-left → double rotation
Final tree:      30
               /    \
             20      40
            /  \       \
          10   25       50           preorder 30 20 10 25 40 50, height 2
A plain (unbalanced) BST with the same insertions has height 4 and degenerates to a list-like shape.

7. Heaps, Hashing & Graph Representation

Priority queues, constant-time lookup by key, and how graphs are stored in memory.

Binary heap

A complete binary tree stored in an array. Max-heap: every parent ≥ its children (the maximum is at the root); min-heap: every parent ≤ its children. With 1-based indexing: left child 2i, right child 2i+1, parent ⌊i/2⌋. A heap with n nodes has height ⌊log₂ n⌋ and ⌈n/2⌉ leaves (the last ⌈n/2⌉ array positions).

OperationTimeHow
Find max (min-heap: min)O(1)root
InsertO(log n)place at the end, sift up while larger than the parent
Delete maxO(log n)move the last element to the root, sift down (swap with the larger child)
Build heap from n elementsO(n)sift down every internal node from ⌊n/2⌋ down to 1 (inserting one by one costs O(n log n))
HeapsortO(n log n)build max-heap, then repeatedly swap the root to the end and sift down; in place, not stable
Search for an arbitrary keyO(n)a heap is not ordered across subtrees
Find the minimum in a max-heapO(n)it is one of the leaves
Worked numerical — bottom-up build and one insertion
Build a max-heap from [4, 10, 3, 5, 1]   (n = 5, internal nodes at positions 2 and 1)
 sift-down position 2 (10): children 5, 1 → fine
 sift-down position 1 (4):  swap with 10 → [10, 4, 3, 5, 1];  4 then swaps with 5 → [10, 5, 3, 4, 1]
 Result: [10, 5, 3, 4, 1]   (2 swaps)

Insert 14 into the max-heap [15, 10, 12, 8, 9, 4, 3]:
 append → [15, 10, 12, 8, 9, 4, 3, 14];  14 > parent 8 → swap;  14 > parent 10 → swap;  14 < 15 stop
 Result: [15, 14, 12, 10, 9, 4, 3, 8]   (2 swaps)

Delete max from [20, 15, 12, 8, 9, 4, 3]: root ← last (3) → sift down: 3 ↔ 15, then 3 ↔ 9 → [15, 9, 12, 8, 3, 4]
Worked numerical — inserting 1, 2, 3, 4, 5 one by one into a max-heap
Each new key is larger than everything before, so it climbs to the root: swaps = 0 + 1 + 1 + 2 + 2 = 6, final array [5, 4, 2, 1, 3]. Building the same heap bottom-up from [1,2,3,4,5] needs fewer swaps — one reason build-heap is O(n) rather than O(n log n).

Hashing

A hash function h(k) maps a key to a slot in a table of size m. With n keys the load factor is α = n / m. A collision happens when two keys hash to the same slot.

MethodHow collisions are handledNotes
Chainingeach slot holds a linked listα can exceed 1; average search ≈ 1 + α; worst O(n)
Linear probingtry h(k)+1, +2, … (mod m)simple, cache friendly; suffers primary clustering
Quadratic probingtry h(k)+1², +2², …avoids primary clustering; may not visit every slot
Double hashingtry h₁(k) + i·h₂(k)closest to uniform hashing; h₂(k) must be non-zero and coprime to m
  • Open addressing stores everything in the table, so n ≤ m (α ≤ 1). Expected probes for an unsuccessful search ≈ 1/(1 − α). Deleting a key must leave a tombstone marker, otherwise later searches stop too early.
  • Good hash functions spread keys uniformly; the division method h(k) = k mod m works best with m prime and not close to a power of 2.
  • Average search/insert/delete is O(1); the worst case is O(n). Hash tables do not support ordered operations (min, range queries) efficiently.
Worked numerical — collision resolution (m = 10, h(k) = k mod 10)
Insert 31, 12, 41, 22, 32, 13. 
Linear probing:    31→1   12→2   41→1✗2✗→3   22→2✗3✗→4   32→2✗3✗4✗→5   13→3✗4✗5✗→6
   table: [_, 31, 12, 41, 22, 32, 13, _, _, _]       probes: 1, 1, 3, 3, 4, 4  (total 16)
Quadratic (+i²):   table: [_, 31, 12, 22, 13, 41, 32, _, _, _]      (41 lands at slot 1+4 = 5)
Chaining:          slot 1: 31 → 41     slot 2: 12 → 22 → 32     slot 3: 13
Note how linear probing builds one long cluster (slots 1–6) — new keys hashing anywhere into it must probe to its end.
Worked numerical — load factor
1000 keys in a chained table of 200 slots: α = 1000 / 200 = 5 — the average chain holds 5 keys.

8. Problem → Standard Method Playbook

Canonical C-language and data-structure procedures for the recurring GATE problem types.

1. Pointer declarators: array of pointers vs pointer to array

Method: start at the identifier and read the declaration outward, respecting parentheses. int *p[5] means an array of 5 pointers to int; int (*p)[5] means a pointer to an array of 5 int. For function pointers, parentheses around *name are essential.
Worked problem — declaration parsing
Q: What is int (*p)[10]?

Answer: p is a pointer to an array of 10 integers. Thus p+1 advances by 10*sizeof(int) bytes, not by one integer.

2. Integer promotions and usual arithmetic conversions

Method: identify the operands' types before evaluating the operator. Smaller integer types undergo integer promotion (commonly to int/unsigned int); then the usual arithmetic conversions determine the common type. Only after the type conversion should you reason about signedness, overflow, shifts, and the final value.
Common trap
Never assume the type of the result from the variable receiving it. The expression is evaluated in its converted operand type first.
Worked problem — promotion
Q: If char a=200, b=100; on a system where plain char is unsigned, what type is used for a+b?

Solution: both char operands undergo integer promotion to int (assuming int can represent all their values). Therefore the addition is performed as int.

3. typedef, enum and volatile

typedef creates an alias for a type; it does not create a new distinct runtime type. enum declares named integer constants and an enumeration type. volatile tells the compiler that an object's value may change for reasons outside ordinary program flow, so accesses must not be optimized away merely because the compiler sees no ordinary write.
Common trap
volatile does not make an operation atomic and does not provide thread synchronization by itself.

4. Bit fields and object representation

Recognition: declarations such as unsigned x:3; inside a structure. A bit-field allocates a specified number of bits, but layout/order, packing, and some alignment details are implementation-defined. For GATE questions, follow the stated implementation assumptions rather than importing a platform-specific ABI rule.

5. Morris inorder traversal / threaded-tree reasoning

Method: if the current node has no left child, visit it and move right. Otherwise find its inorder predecessor in the left subtree. If the predecessor's right link is null, create a temporary thread to the current node and move left; if the thread already points to the current node, remove it, visit the current node, and move right. Extra auxiliary space is O(1).
Worked problem — Morris traversal
Q: What is the inorder sequence of a BST containing 4 as root, 2 and 6 as children, and 1,3,5,7 as leaves?

Answer: 1,2,3,4,5,6,7. Morris traversal produces the same inorder sequence as recursive traversal while using O(1) auxiliary space (ignoring the output).

6. Data-structure recognition

Stack: LIFO; balanced-parenthesis and DFS-style applications. Queue: FIFO; BFS and scheduling. Heap: complete tree + heap order; priority queue. BST: ordered search tree; inorder is sorted. Hash table: expected O(1) lookup under suitable hashing/load assumptions, but no efficient ordered traversal. Adjacency list: Θ(V+E); adjacency matrix: Θ(V²).
Worked problem — choose the structure
Q: A system repeatedly needs the smallest-priority item, while insertions are frequent. Which standard structure should be considered first?

Answer: a binary heap / priority queue. It supports insertion and extract-min/max in O(log n) and gives O(1) access to the current extremum.

Q1 · Integer semantics in C

Q11 · What does it print, and what is its time complexity?
For n = 20, what does the program print, and what is the time complexity of the loop nest as a function of n? 
int count = 0;
for (int i = 1; i <= n; i *= 2)
    for (int j = 0; j < i; j++)
        count++;
printf("%d", count);
  1. 20, Θ(n log n)
  2. 31, Θ(n log n)
  3. 31, Θ(n)
  4. 20, Θ(n)
The outer loop runs with i = 1, 2, 4, 8, 16 (i = 32 fails 32 <= 20).
The inner loop runs i times for each value of i:
   count = 1 + 2 + 4 + 8 + 16 = 31

General case: i takes the values 2^0 ... 2^k with k = floor(log2 n), so
   count = 2^(k+1) - 1 < 2n  ⇒  Θ(n).
Trap: "log n outer iterations × n inner iterations" gives n log n, but the inner
bound is i, not n — the sum is a geometric series dominated by its last term.

Correct: Option 3 — prints 31, time Θ(n).

2 [  1  0  0  1  1  0 ]

  2. BFS 0 1 2 3 4 5; DFS 0 1 4 2 3 5

Q14 · Bitwise operators — output and precedence trap
What does the following program print?
unsigned int x = 0xB6; /* 1011 0110 */
int cnt = 0; unsigned t = x;
while (t) { t = t & (t - 1); cnt++; }
printf("%u %u %d %u", x & (x - 1), x & -x, cnt, (x >> 2) ^ (x << 1) & 0xFF);
  1. 180 2 5 65
  2. 180 2 5 45
  3. 182 2 5 65
  4. 180 4 6 65
x = 0xB6 = 1011 0110 (decimal 182).

x & (x − 1)  : subtracting 1 turns the lowest set bit into 0 and the zeros below it into 1s, so AND clears the lowest set bit
               1011 0110 & 1011 0101 = 1011 0100 = 0xB4 = 180
x & −x       : −x is the two's complement, so the AND keeps ONLY the lowest set bit
               1011 0110 & (…0100 1010) = 0000 0010 = 2
cnt          : the loop clears one set bit per pass (Kernighan's trick), so it counts the 1 bits of x: 1011 0110 has 5 → 5
Last value   : precedence is  shift  >  &  >  ^, so it parses as  (x >> 2) ^ ((x << 1) & 0xFF)
               x >> 2 = 0010 1101 = 45;   (x << 1) & 0xFF = 0x16C & 0xFF = 0x6C = 108;   45 ^ 108 = 0010 1101 ^ 0110 1100 = 0100 0001 = 65

Printed: 180 2 5 65.
Check: the program was compiled and run; it prints exactly "180 2 5 65".
Trap: writing ((x >> 2) ^ (x << 1)) & 0xFF gives a different answer — & binds tighter than ^.

Correct: Option 1 — the output is 180 2 5 65.

Q15 · Storage classes — static local, global and block scope
What is printed by the following program?
int g = 10;
int f(void) { static int c = 0; c += g; g -= 3; return c; }
int main(void) {
int a = f();
{ int g = 100; g += f(); printf("%d ", g); }
int b = f();
printf("%d %d %d", a, b, g);
}
  1. 117 10 21 1
  2. 117 10 21 10
  3. 110 10 21 1
  4. 117 10 27 7
Two different things are tested: a static local keeps its value between calls, and an inner block's g hides the global g ONLY inside that block's source text — the function f always refers to the global g.

Call 1 (a = f()):  c = 0 + 10 = 10;   global g becomes 7;        a = 10
Inner block:       local g = 100.  f() runs: c = 10 + 7 = 17 (it uses the GLOBAL g = 7), global g becomes 4, returns 17.
                   local g = 100 + 17 = 117 → prints "117 "
Call 3 (b = f()):  c = 17 + 4 = 21;   global g becomes 1;        b = 21
Final printf (outside the block, so g is the global again): a = 10, b = 21, g = 1.

Printed: 117 10 21 1.
Check: compiled and run; output "117 10 21 1".
Trap: static c is initialised ONCE (at program start), not on every call; and scope is lexical, so f never sees the block's g.

Correct: Option 1 — the output is 117 10 21 1.

Q16 · Two-dimensional arrays and pointer arithmetic
int a[4][5] is stored in row-major order with sizeof(int) = 4 and base address 1000. What are the addresses of &a[2][3], (a + 1) and (*(a + 1) + 2)?
  1. 1052, 1020 and 1028
  2. 1052, 1004 and 1028
  3. 1048, 1020 and 1024
  4. 1052, 1020 and 1020
Row-major address of a[i][j] = base + (i × columns + j) × size  = 1000 + (i × 5 + j) × 4.

&a[2][3]       : (2×5 + 3) × 4 = 52                → 1052
a + 1          : a has type int (*)[5] ('pointer to a row of 5 ints'), so adding 1 moves a WHOLE ROW = 5 × 4 = 20 bytes → 1020
*(a + 1)       : the row a[1], which decays to int * pointing at a[1][0] (address 1020)
*(a + 1) + 2   : now the step is ONE int (4 bytes): 1020 + 2×4 = 1028   (= &a[1][2])

Useful identities:  a[i][j] ≡ *(*(a + i) + j) ≡ *(a[i] + j);   sizeof(*a) = 20,  sizeof(a) = 80,  (a + 3) − a = 3 (rows).
Check: compiled and run — byte offsets from a come out as 52, 20 and 28, and &a[2][3] − &a[0][0] = 13 ints.
Trap: a + 1 skips a row, not one int — the pointer's TYPE decides the step size.

Correct: Option 1 — the addresses are 1052, 1020 and 1028.

Q17 · Rebuilding a binary tree from preorder and inorder
The preorder traversal of a binary tree is A B D G H E C F I and its inorder traversal is G D H B E A C I F. What is the postorder traversal and the height of the tree (in edges)?
  1. G H D E B I F C A, height 3
  2. G H D E B F I C A, height 3
  3. G H D E B I F C A, height 4
  4. H G D E B I F C A, height 3
Method: the FIRST preorder symbol is the root; in the inorder sequence everything to its left is the left subtree and everything to its right is the right subtree; recurse.

Root A.  Inorder split:  left = G D H B E   |   right = C I F
  left subtree (preorder B D G H E):   root B;  inorder G D H | E  →  B has left subtree {G D H}, right child E
      {G D H} (preorder D G H):   root D, left child G, right child H
  right subtree (preorder C F I):      root C;  inorder (empty) | I F →  C has no left child, right subtree {I F}
      {I F} (preorder F I):            root F, left child I

Tree:      A
         /   \
        B     C
       / \     \
      D   E     F
     / \       /
    G   H     I

Postorder (left, right, root):  G H D E B I F C A.
Height: longest root-to-leaf path = A–B–D–G (3 edges) = A–C–F–I (3 edges) → 3.   Leaves: G, H, E, I.
Check: the tree was rebuilt by program from the two sequences (unique, because all keys are distinct); postorder GHDEBIFCA, height 3.
Trap: preorder + postorder do NOT determine a tree uniquely, but preorder + inorder (or postorder + inorder) always do.

Correct: Option 1 — postorder G H D E B I F C A, height 3.
