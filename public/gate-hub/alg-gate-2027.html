1. Asymptotic Analysis & Recurrences

How running time and space are measured as input size grows, and the standard techniques for solving the recurrences that recursive algorithms produce.

Asymptotic notation

NotationMeaningRead as
f = O(g)f(n) ≤ c·g(n) for all n ≥ n₀g is an upper bound
f = Ω(g)f(n) ≥ c·g(n) for all n ≥ n₀g is a lower bound
f = Θ(g)both O(g) and Ω(g)tight bound (same growth rate)
f = o(g) / ω(g)f/g → 0 / f/g → ∞strictly smaller / larger
  • Constants and lower-order terms are dropped: 5n² + 3n log n = Θ(n²). The base of a logarithm only changes a constant factor, so log₂n = Θ(log₁₀n); but 2n and 4n are not Θ of each other (the base of an exponential matters).
  • Worst, average and best case are different functions of n; O/Ω/Θ describe bounds on whichever function you chose. "Insertion sort is Ω(n)" (best case) and "O(n²)" (worst case) are both true.
  • Transitivity holds for O, Ω, Θ; Θ is symmetric; f = O(g) ⇔ g = Ω(f).

Growth-rate ladder

1  <  log log n  <  log n  <  (log n)^k  <  n^ε  <  n  <  n log n  <  n²  <  n³  <  2ⁿ  <  n!  <  nⁿ
  • Any polynomial beats any polylog; any exponential beats any polynomial.
  • nlog n = 2(log n)² grows faster than every polynomial but slower than 2n, because (log n)² = o(n).
  • log(n!) = Θ(n log n) (Stirling). Also √n is much bigger than log n; n0.01 beats (log n)100 eventually.
  • Compare functions by taking logs or by limits: lim f/g = 0 ⇒ f = o(g).

Analysing loops

Worked numerical — nested loop with a doubling outer index
for (i = 1; i <= n; i *= 2)
    for (j = 1; j <= i; j++)
        count++;
i takes the values 1, 2, 4, …, 2^k  with k = ⌊log₂ n⌋
count = 1 + 2 + 4 + … + 2^k = 2^(k+1) − 1  <  2n
n = 16 → 31       n = 100 → 1 + 2 + 4 + 8 + 16 + 32 + 64 = 127       →  Θ(n), not Θ(n log n)
  • for (i = 1; i < n; i *= 2) runs ⌈log₂ n⌉ times. for (i = 1; i*i <= n; i++) runs ⌊√n⌋ times (n = 100 → 10).
  • Nested independent loops multiply: n × (log n) × … ; when the inner bound depends on the outer index, sum the series instead.
  • For for (i = n; i > 1; i = √i) the count is Θ(log log n).
  • Space complexity counts extra memory beyond the input, including the recursion stack depth.

Q: Solve T(n) = 2T(n/2) + n log n.

2. Searching & Sorting

The standard sorting algorithms, their cost in the best, average and worst case, the Ω(n log n) lower bound, and the comparison counts GATE likes to ask for.

Searching

  • Linear search: Θ(n) worst case, (n+1)/2 comparisons on average for a successful search.
  • Binary search on a sorted array: at most ⌊log₂ n⌋ + 1 comparisons (n = 15 → 4, n = 1000 → 10 because 2¹⁰ = 1024). Recurrence T(n) = T(n/2) + 1. Not possible in O(log n) on a linked list.
  • Interpolation search: O(log log n) on uniformly distributed data, O(n) worst case. Hash search: O(1) average.

A sort is stable if equal keys keep their original relative order, and in place if it uses O(1) extra memory. Selection sort makes at most n−1 swaps (the fewest of the simple sorts); insertion sort is best for nearly sorted data and small arrays; merge sort is the choice for linked lists and external sorting.

Lower bound and non-comparison sorts

  • Any comparison sort corresponds to a binary decision tree with at least n! leaves, so its height is ≥ ⌈log₂ n!⌉ = Ω(n log n). Sorting 5 items needs at least ⌈log₂ 120⌉ = 7 comparisons in the worst case.
  • Counting sort: keys are integers in 0…k; Θ(n + k) time and space, stable. Radix sort: d passes of a stable sort, Θ(d(n + k)). Bucket sort: Θ(n) expected for uniform input. These beat n log n only because they do not compare keys.

Counting operations

Inversions
A pair i < j with a[i] > a[j]. Maximum n(n−1)/2 (reverse sorted). Insertion sort performs exactly one shift per inversion; bubble sort performs exactly one swap per inversion.

Worked numerical — inversions and shifts

Worked numerical — quicksort worst case
With the first (or last) element as the pivot, an already sorted array splits into 0 and n−1 elements every time, so comparisons = (n−1) + (n−2) + … + 1 = n(n−1)/2: n = 6 → 15, n = 8 → 28 (counted by running the algorithm). The recurrence is T(n) = T(n−1) + n, i.e. Θ(n²). Randomised pivot or median-of-three avoids this on sorted input; expected comparisons ≈ 2n ln n ≈ 1.39 n log₂ n.
Worked numerical — merge sort comparisons (n = 8)
Worst case = 8·3 − 8 + 1 = 17 comparisons, best case = 12 (n/2 · log₂ n). Both values were confirmed by sorting all 8! = 40 320 permutations and recording the minimum and maximum comparison counts.

Selection problems

  • Quickselect (k-th smallest): partition around a pivot and recurse into one side — O(n) average, O(n²) worst.
  • Median of medians guarantees a good pivot (groups of 5), giving O(n) worst case: T(n) = T(n/5) + T(7n/10) + O(n).
  • Finding the maximum needs exactly n − 1 comparisons. Finding max and min together takes ⌈3n/2⌉ − 2 (compare in pairs first): n = 8 → 10, n = 100 → 148 (verified by simulation).
GATE angle
Know which sort is stable, in place, adaptive (insertion), and which has an O(n²) worst case (quick, insertion, bubble, selection). Expect questions on number of swaps/comparisons for a given array, effect of the pivot rule and "which sorting algorithm will take the least time on an already sorted input" (insertion sort: Θ(n)).

3. Divide & Conquer

Split the problem into independent subproblems, solve each recursively, and combine the results. The running time is a recurrence T(n) = aT(n/b) + f(n).

The pattern

  1. Divide the input into a smaller instances of size n/b.
  2. Conquer by solving them recursively (base case for tiny inputs).
  3. Combine the answers in f(n) time.

Worked ideas

Worked numerical — Strassen
Naive 2×2 block multiplication needs 8 recursive products, giving n³. Strassen uses 7 products plus extra additions (Θ(n²) work). 
fully recursing an 8×8 matrix down to 1×1 scalars:
   naive:    8³ = 512 scalar multiplications
   Strassen: 7³ = 343 scalar multiplications          (4×4: 49 vs 64)

Worked numerical — fast exponentiation (square and multiply)
x¹³: 13 = 1101₂. Squarings needed = ⌊log₂13⌋ = 3 and extra multiplications = (number of 1 bits) − 1 = 2, so 5 multiplications instead of 12. x¹⁵ needs 6, x¹⁶ needs only 4.
Worked numerical — max and min with n = 8
Recurrence T(2) = 1, T(n) = 2T(n/2) + 2 → T(n) = 3n/2 − 2 = 10 for n = 8. Compare this with the straightforward 2(n − 1) = 14 comparisons.
  • Merge step of merge sort uses O(n) extra space; sorting an array of n elements has recursion depth log₂ n.
  • Counting inversions in O(n log n): piggy-back on merge sort — when an element from the right half is merged before elements of the left half, it forms inversions with all remaining left elements.
  • Efficiency of D&C comes from the combine cost: if the subproblems overlap (e.g. Fibonacci), plain D&C is exponential and dynamic programming is needed instead.

4. Greedy Algorithms

Make the locally best choice at each step and never reconsider. It works only when the problem has the greedy-choice property and optimal substructure.

When greedy works

  • Greedy-choice property: some optimal solution contains the greedy first choice (proved by an exchange argument: swap any optimal solution's first choice for the greedy one without making it worse).
  • Optimal substructure: after the greedy choice, the rest is a smaller instance of the same problem.
  • Greedy algorithms are usually simple and fast (often O(n log n) because of a sort or a heap) but can be wrong: always look for a counter-example.

Worked numerical — Huffman coding
Q: Frequencies (per 100 characters): a 45, b 13, c 12, d 16, e 9, f 5. Find the total encoded length.
A: Merge the two smallest repeatedly: f+e = 14; c+b = 25; 14+d = 30; 25+30 = 55; a+55 = 100. 
code lengths:  a = 1,  b = 3,  c = 3,  d = 3,  e = 4,  f = 4

Worked numerical — coin change where greedy fails
Coins {1, 3, 4}, amount 6: greedy takes 4 + 1 + 1 = 3 coins, but 3 + 3 = 2 coins is optimal. Greedy is correct for canonical systems such as {1, 5, 10, 25} and for {1, 2, 5, 10}.

5. Dynamic Programming

Solve each subproblem once and store the answer. It applies when the problem has optimal substructure and overlapping subproblems.

Method

  1. Define the subproblem (the state) and what the table entry means.
  2. Write the recurrence that builds a state from smaller ones, plus the base cases.
  3. Fill the table in an order that respects dependencies (tabulation, bottom-up) or recurse with a cache (memoisation, top-down).
  4. Time = (number of states) × (work per state); space = table size (often reducible to one or two rows).

DP vs divide & conquer: D&C subproblems are independent; DP subproblems overlap. DP vs greedy: DP examines all choices (guaranteed optimal when the structure holds); greedy commits to one. Naive recursion on overlapping subproblems is exponential — Fibonacci with memoisation drops from Θ(φⁿ) to Θ(n).

6. Graph Algorithms

Traversal, topological ordering, strongly connected components, minimum spanning trees and shortest paths. V = number of vertices, E = number of edges.

Traversal: BFS and DFS

  • BFS (queue): visits vertices in increasing distance (number of edges) from the source; gives shortest paths in unweighted graphs; Θ(V + E) with adjacency lists, Θ(V²) with a matrix. A graph is bipartite iff BFS can 2-colour it (no odd cycle).
  • DFS (stack / recursion): records discovery and finish times; Θ(V + E). Edge types in a directed graph: tree, back, forward, cross. A directed graph has a cycle iff DFS finds a back edge; an undirected graph has a cycle iff DFS meets a visited vertex that is not the parent.
  • A DFS forest of an undirected graph with c components has V − c tree edges. Articulation points and bridges are found with DFS low-link values in Θ(V + E).

Topological sort and SCC

  • A topological ordering (every edge u → v has u before v) exists iff the graph is a DAG. Two methods, both Θ(V + E): (1) Kahn — repeatedly remove a vertex of in-degree 0; (2) DFS — output vertices in decreasing finish time. The ordering is usually not unique.
  • Strongly connected components: Kosaraju (DFS on G, then DFS on the transpose in decreasing finish time) or Tarjan (one DFS with low-links), both Θ(V + E). Contracting each SCC gives a DAG.
Worked numerical — counting topological orderings
DAG on vertices 0–5 with edges 5→2, 5→0, 4→0, 4→1, 2→3, 3→1. Kahn's algorithm with the smallest-index rule gives 4 5 0 2 3 1. Counting all linear extensions (by testing every permutation of the 6 vertices) gives 13 valid topological orders.
Worked numerical — SCCs
Directed graph: 0→1, 1→2, 2→0, 2→3, 3→4, 4→5, 5→3, 6→5, 6→7, 7→6. SCCs: {0,1,2}, {3,4,5}, {6,7} — three components, and the condensation DAG is {6,7} → {3,4,5} ← {0,1,2}.

Minimum spanning tree

  • An MST of a connected weighted graph has V − 1 edges and minimum total weight. If all edge weights are distinct, the MST is unique.
  • Cut property: for any cut, the lightest crossing edge belongs to some MST. Cycle property: the heaviest edge on a cycle (if unique) belongs to no MST.
  • Kruskal: sort edges, add the next edge if it joins two different components (union-find). Θ(E log E) = Θ(E log V).
  • Prim: grow one tree from a start vertex, always adding the cheapest edge leaving it. Θ(E log V) with a binary heap; Θ(V²) with an adjacency matrix and no heap; Θ(E + V log V) with a Fibonacci heap.
  • Adding the same constant to every edge, or squaring all positive weights, does not change which spanning tree is minimum (only the ordering of weights matters).

7. Amortized Analysis, Hashing & NP-Completeness

Average cost over a sequence of operations, expected cost of hashing, and the classification of problems by how hard they are to solve.

Amortized analysis

The amortized cost of an operation is the average over a worst-case sequence — no probability involved. Three methods: aggregate (total ÷ n), accounting (charge extra credit to cheap operations), potential (a potential function Φ ≥ 0, amortized cost = actual + ΔΦ).

Worked numerical — dynamic array doubling
Push onto an array whose capacity doubles when full. Copies happen at sizes 1, 2, 4, 8, … For n = 16 pushes: 16 writes + (1 + 2 + 4 + 8) = 15 copies = 31 total, i.e. under 2 per push. In general the total is < 3n, so the amortized cost per push is O(1) even though a single push can cost Θ(n).
Worked numerical — binary counter
Incrementing a k-bit counter flips many bits occasionally. Total flips over n increments from 0 equals 2n − (number of 1s in n): n = 8 → 15, n = 16 → 31, n = 100 → 197. So the amortized cost per increment is < 2 flips = O(1).
  • Union–find with union by rank and path compression: m operations cost O(m·α(n)), where α is the inverse Ackermann function (≤ 4 for any practical n).
  • Stack with multipop, queue from two stacks, and splay trees are standard amortized examples.

Hashing — analysis

  • With chaining and simple uniform hashing, load factor α = n/m: expected unsuccessful search Θ(1 + α), successful ≈ 1 + α/2. With α = O(1), operations are O(1) expected.
  • Open addressing, uniform probing: expected probes ≈ 1/(1 − α) for an unsuccessful search and (1/α)·ln(1/(1 − α)) for a successful one.
  • A universal family of hash functions makes the expected number of collisions small regardless of the input. The birthday paradox: collisions are likely once about √m keys are inserted. Cuckoo hashing gives worst-case O(1) lookups.

P, NP and NP-completeness

ClassDefinition
Pdecision problems solvable in polynomial time by a deterministic algorithm
NPproblems whose "yes" answers can be verified in polynomial time given a certificate (equivalently, solvable by a non-deterministic polynomial-time machine). P ⊆ NP.
NP-hardat least as hard as every problem in NP (every NP problem reduces to it); need not be in NP
NP-completein NP and NP-hard
  • Polynomial-time reduction A ≤p B: an easy translation of instances of A into instances of B. If B is easy then A is easy; if A is hard then B is hard. To prove B NP-hard, reduce a known NP-complete problem to B (direction matters!).
  • Cook–Levin theorem: SAT is NP-complete (the first one). If any NP-complete problem is in P, then P = NP; if any is proved to need super-polynomial time, then P ≠ NP.
NP-completeIn P (polynomial time)
SAT, 3-SAT, Clique, Independent Set, Vertex Cover, Hamiltonian cycle/path, Travelling Salesman (decision), Subset Sum, Partition, 3-colouring, 0/1 knapsack (decision), Set cover2-SAT, shortest paths, MST, matching, maximum flow, 2-colouring (bipartiteness), Euler circuit, linear programming, primality testing (AKS), sorting, searching
Worked numerical — vertex cover and independent set are complements
Fact: S is a vertex cover of G iff V − S is an independent set. So min vertex cover + max independent set = |V|. Check on the graph with edges 0–1, 1–2, 2–3, 3–4, 4–0, 0–5 (a 5-cycle with a pendant vertex): minimum vertex cover = 3 ({0, 2, 3} works), maximum independent set = 3 ({1, 3, 5}), and 3 + 3 = 6 = |V| (checked by brute force over all subsets).
  • Pseudo-polynomial algorithms run in time polynomial in the numeric value of the input (knapsack Θ(nW)); NP-complete problems that have them are only "weakly" NP-complete.
  • Approximation: vertex cover has a simple 2-approximation (take both endpoints of a maximal matching); metric TSP has a 2-approximation (double the MST) and Christofides' 1.5.
  • Relationship of classes believed true: P ⊂ NP ⊂ PSPACE ⊂ EXPTIME (P ≠ NP is an open question). Co-NP contains the complements of NP problems; P ⊆ NP ∩ co-NP.
GATE angle
Typical questions: "which of these is not known to be NP-complete / is in P" (2-SAT, shortest path, MST are in P; 3-SAT, Clique, Hamiltonian cycle, Subset Sum are NPC), "what follows if X is in P", and which direction a reduction must go. The decision version of a problem is the one that is NP-complete; the optimisation version is NP-hard.

8. Problem → Standard Method Playbook

Standard GATE methods for the remaining high-yield algorithmic patterns. Identify the problem family first, then apply the canonical algorithm.

Heap Sort — canonical procedure

  1. Build a max-heap for ascending order (bottom-up heapify, O(n)).
  2. Swap the root with the last element of the active heap.
  3. Reduce heap size by one and max-heapify the root.
  4. Repeat until one element remains.

Time: O(n log n) in best/average/worst cases. Auxiliary array space: O(1) for in-place heap sort. It is not stable.

Open addressing — double hashing

For table size m, the standard probe sequence is:

h(k,i) = (h₁(k) + i·h₂(k)) mod m, i = 0,1,2,…
  • Choose h₂(k) relatively prime to m so the sequence can visit the entire table.
  • Do not confuse double hashing with linear probing: linear probing adds a fixed step of 1.
  • Deletion normally uses a tombstone/deleted marker; simply clearing a slot can break future searches.

BFS / DFS — recognition and invariants

  • BFS: queue; explores by nondecreasing distance from the source. In an unweighted graph, first discovery gives a shortest-path distance.
  • DFS: recursion/explicit stack; timestamps classify edges and support cycle detection, topological ordering, SCCs and articulation/bridge algorithms.
  • For an undirected graph, DFS produces tree/back edges; a cross-edge classification from directed DFS should not be imported blindly.

Articulation point — Tarjan low-link test

During DFS, maintain disc[u] and low[u]. For a DFS tree edge u→v:

  • If u is not the root: u is an articulation point iff some child v has low[v] ≥ disc[u].
  • If u is the DFS root: it is an articulation point iff it has at least 2 DFS children.
  • For an undirected graph, a bridge is detected by low[v] > disc[u].

Greedy vs DP — selection test

Before choosing an algorithm, ask:

  1. Does a locally optimal choice provably extend to a global optimum? → seek a greedy-choice/exchange proof.
  2. Do many subproblems overlap and can an optimal solution be decomposed into optimal subsolutions? → use DP.
  3. If neither property is apparent, do not force greedy or DP; consider graph search, divide-and-conquer, backtracking, or another formulation.
Worked problem — double hashing
Table size m=11, h₁(k)=k mod 11, h₂(k)=7−(k mod 7). Insert 22, 33, 44 using open addressing. 
22: h₁=0, h₂=6 → slot 0.
33: h₁=0, h₂=2 → slot 0 occupied, then (0+2) mod 11 = 2.
44: h₁=0, h₂=5 → slot 0 occupied, then 5 is free.
Final occupied slots: 0→22, 2→33, 5→44.
Worked problem — articulation point
DFS tree: 1→2, 2→3, 3→4, with a back edge 4→2. Is 2 an articulation point?

disc[2] < disc[3].
The subtree rooted at 3 has a back edge to 2, so low[3] = disc[2].
Articulation condition for non-root 2 is low[3] ≥ disc[2].
Equality holds → vertex 2 is an articulation point (removing it separates 1 from the {3,4} part).
Worked problem — heap sort
Build a max-heap from [4, 1, 3, 2]. 
Start: [4,1,3,2].
Heapify index 1: 1 has child 2 → swap → [4,2,3,1].
Index 0 already has largest child 4.
Max-heap = [4,2,3,1].
Then repeatedly swap root with the last active element and heapify the reduced heap.

Tree edges: A–B, B–C, B–D, D–E, E–F, F–G (6 = |V| − 1);   back edges: C→A and F→D (2);   8 edges in all = 6 + 2.
Finishing order: C, G, F, E, D, B, A.

Articulation points (Tarjan's low-link test):
   disc:  A1 B2 C3 D5 E6 F7 G8        low:  A1 B1 C1 D5 E5 F5 G8
   non-root vertex u with a child v is an articulation point if  low[v] ≥ disc[u]:
   B (child D: low 5 ≥ disc 2 ✔),  D (child E: low 5 ≥ disc 5 ✔),  F (child G: low 8 ≥ disc 7 ✔).
   Root A has only ONE DFS child (B), so A is not an articulation point.
   C has no DFS children and E fails the test (child F has low 5 < disc 6 ✘), so neither is an articulation point.
So the articulation points are B, D and F (bridges: B–D and F–G).
Check: low-link values and the set {B, D, F} were confirmed with an independent graph-library computation.

Q17 · Longest common subsequence — table and number of LCSs
For X = ABCBDAB and Y = BDCABA, what is the length of the longest common subsequence and how many DISTINCT longest common subsequences exist?
  1. Length 4, exactly 3 distinct LCSs
  2. Length 4, exactly 1 LCS
  3. Length 5, exactly 3 distinct LCSs
  4. Length 4, exactly 2 distinct LCSs
Recurrence:  L[i][j] = L[i−1][j−1] + 1  if X[i] = Y[j],   else  max( L[i−1][j], L[i][j−1] ).

        ''  B  D  C  A  B  A
   ''    0  0  0  0  0  0  0
   A     0  0  0  0  1  1  1
   B     0  1  1  1  1  2  2
   C     0  1  1  2  2  2  2
   B     0  1  1  2  2  3  3
   D     0  1  2  2  2  3  3
   A     0  1  2  2  3  3  4
   B     0  1  2  2  3  4  4        →  L[7][6] = 4

Tracing back (up when the upper cell is at least as large, left when the left is at least as large — and exploring BOTH when they tie)
yields the distinct strings  BCAB,  BCBA  and  BDAB.   Time and space are O(mn) (O(min(m, n)) space if only the length is needed).
Check: a brute-force search over all 2^7 subsequences of X found the same maximum length 4 and exactly these 3 common subsequences.
Trap: stopping at the first traceback path reports ONE LCS; the LCS is not unique in general.

Correct: Option 1 — length 4, with 3 distinct LCSs (BCAB, BCBA, BDAB).

Q18 · Quick sort — first partition and worst-case comparisons
Quick sort uses Lomuto partitioning with the LAST element as pivot (scan j from the first element, move every element ≤ pivot to the left part, finally place the pivot). For A = [9, 4, 6, 2, 8, 5, 7, 3], what is A after the first partition, and how many comparisons does Quick sort make in total on an already sorted array of 8 elements?
  1. [2, 3, 6, 9, 8, 5, 7, 4]; 28
  2. [2, 3, 6, 9, 8, 5, 7, 4]; 24
  3. [2, 4, 6, 9, 8, 5, 7, 3]; 28
  4. [3, 4, 6, 2, 8, 5, 7, 9]; 28
Pivot = 3 (last element); i starts at −1 and counts the elements ≤ pivot found so far.
  j=0: 9 > 3   j=1: 4 > 3   j=2: 6 > 3
  j=3: 2 ≤ 3 → i = 0, swap A[0] ↔ A[3]  → [2, 4, 6, 9, 8, 5, 7, 3]
  j=4: 8   j=5: 5   j=6: 7   (all > 3)         — 7 comparisons (n − 1) in this partition
  place the pivot: swap A[i+1] = A[1] with A[7] → [2, 3, 6, 9, 8, 5, 7, 4]   (pivot 3 is now at index 1, final position)

Sorted input with the last element as pivot: the pivot is the maximum, so the partition is as unbalanced as possible (n − 1 and 0).
   T(n) = T(n − 1) + (n − 1) comparisons  →  7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 = n(n − 1)/2 = Θ(n²).
A reverse-sorted array also gives 28 with this pivot rule. Choosing a random pivot or the median of three makes the bad case unlikely: expected Θ(n log n).
Check: Lomuto partition and the full recursion were run by program: array after the first pass [2, 3, 6, 9, 8, 5, 7, 4]; 28 comparisons on sorted input.

Correct: Option 1 — the first pass gives [2, 3, 6, 9, 8, 5, 7, 4] and a sorted array costs 28 comparisons.
