1. Number Systems & Computer Arithmetic

How a computer stores numbers, and how it adds/subtracts/represents fractions — the base layer under everything else in COA.

Signed number representation 🟢 Core

A computer only has 0s and 1s. To represent negative numbers, we use one of three schemes on an n-bit word. GATE almost only cares about the third one.

SchemeHow -5 (4-bit) looksProblem
Sign-magnitude1101 (sign bit + magnitude 101)two zeros (+0, -0), messy arithmetic
1's complement1010 (flip all bits of 5=0101)still two zeros, needs "end-around carry"
2's complement1011 (flip bits, +1)none — this is what real CPUs use
Rule of thumb
To get -x in 2's complement: flip every bit of x, then add 1. To go back from a negative 2's complement number to decimal: flip every bit, add 1, put a minus sign in front.

Range you must memorize

For an n-bit signed 2's complement number: 
Range = -2^(n-1)  to  +2^(n-1) - 1
So for n = 8: -128 to +127. Notice it's asymmetric — one extra negative number, because there's only one zero.
Worked numerical (GATE style)
Q: What is the range of integers representable in 12-bit 2's complement form?
A: n=12 → from −2¹¹ to +2¹¹−1 = −2048 to +2047.

Addition, subtraction & overflow

2's complement lets you subtract by adding the negative. Just add the bit patterns normally and discard any carry-out of the leftmost bit.

Worked numerical
Q: Using 5-bit 2's complement, compute 7 − 3.
A: 7 = 00111, −3 = 11101 (flip 3=00011 → 11100, +1 → 11101).
Add: 00111 + 11101 = 100100 → discard the leading carry → 00100 = 4. Correct!
Overflow detection rule
Overflow happens only when adding two numbers of the same sign and the result has the opposite sign. Formally: overflow = carry into MSB XOR carry out of MSB. GATE loves asking "does this addition overflow?" — check the sign bits first, don't compute the whole thing if you don't have to.
Worked numerical
Q: In 4-bit 2's complement, does 5 + 4 overflow?
A: 5=0101, 4=0100. Sum = 1001 = −7 in 4-bit. Both operands positive, result negative → overflow (the true sum 9 is above the 4-bit signed maximum of +7, so it cannot be represented).

Carry vs overflow, sign extension, and other codes 🔵 High-Yield · frequent PYQ background

FlagMeaningTest
Carry (C)Unsigned result does not fitCarry out of the MSB
Overflow (V)Signed result does not fitCarry into the MSB XOR carry out of the MSB
Worked example
Q: In 4 bits, add 1111 and 0001. Report carry and overflow.
A: 1111 + 0001 = 1 0000, so the result is 0000 with carry = 1. Unsigned, that is 15 + 1 = 16, which does not fit. Signed, it is (−1) + 1 = 0, which is correct: carry into the MSB = 1 and carry out = 1, so XOR = 0 and overflow = 0. The same bit pattern can set one flag and not the other.
Sign extension (widening a 2's-complement number) copies the sign bit into the new high bits: 1101 (−3) in 8 bits is 11111101, still −3. Unsigned numbers are zero-extended instead.

Other codes. BCD: each decimal digit in 4 bits (59 → 0101 1001). Excess-3: BCD digit + 3. Gray code: consecutive values differ in exactly one bit; for 3 bits it runs 000, 001, 011, 010, 110, 111, 101, 100, and Gray = binary XOR (binary >> 1).

2. Instruction Set & Addressing Modes

How a CPU instruction says what to do and where to find its data — the #1 highest-yield COA topic in GATE.

Instruction formats: how many "addresses"? 🟢 Core

An instruction = opcode (what to do) + operands (who to do it to). Older CPUs are classified by how many memory addresses an instruction can reference:

TypeExample (for C = A + B)Used in
3-addressADD C, A, BRISC-like / register machines
2-addressMOV C, A then ADD C, Bx86-style CISC
1-address (accumulator)LOAD A; ADD B; STORE Csimple/old machines
0-address (stack)PUSH A; PUSH B; ADD; POP Cstack machines, JVM
GATE trap
Fewer addresses per instruction ⇒ more instructions needed to do the same job, but each instruction is shorter. GATE often asks you to count total instructions or total bits for a given expression across these formats.

Addressing modes — where is the actual operand? 🟢 Core

The instruction doesn't always contain the value directly. The addressing mode tells the CPU how to compute the Effective Address (EA) — where in memory/registers the real data sits.

Worked numerical
Q: An instruction uses indirect addressing with the address field = 300. Mem[300] = 500, Mem[500] = 42. What is the effective operand?
A: Indirect ⇒ EA = Mem[300] = 500. Operand = Mem[500] = 42. (Indirect addressing costs one extra memory reference compared to direct — this is exactly why GATE loves timing questions: "if memory access = 100ns and indirect mode used, extra time = 100ns per instruction".)
Worked numerical
Q: Register R1 = 2000. Instruction: LOAD R2, 20[R1] using indexed addressing, and Mem[2020] = 77. Find R2 after execution.
A: EA = R1 + 20 = 2000 + 20 = 2020. R2 ← Mem[2020] = 77.

RISC vs CISC (quick contrast, often 1 mark)

RISC
Few, simple, fixed-length instructions. Mostly register-to-register. Simple addressing modes. More instructions needed, but each is fast (1 cycle typical) — pipelines well.
CISC
Many complex, variable-length instructions. Instructions can directly operate on memory. Fewer instructions per program, but each may take several cycles.

Expanding opcodes 🟢 Core · instruction formats

A fixed-length instruction can hold more instruction types by reusing unused opcode patterns as a prefix for a longer opcode. Each time the opcode grows, the address fields shrink to make room.

Worked numerical
Q: A 16-bit instruction has 4-bit address fields. The machine needs 14 three-address instructions, 30 two-address instructions, and as many one-address instructions as possible. How many one-address instructions fit?
A: 
Level 1 (3 addresses): 4-bit opcode, 3 × 4-bit addresses   → 16 patterns, use 14, 2 left
Level 2 (2 addresses): 8-bit opcode, 2 × 4-bit addresses   → 2 × 16 = 32 patterns, use 30, 2 left
Level 3 (1 address)  : 12-bit opcode, 1 × 4-bit address    → 2 × 16 = 32 patterns
So up to 32 one-address instructions. If only 31 were used, 1 pattern would remain: 1 × 16 = 16 zero-address instructions with a 16-bit opcode.

Byte ordering (endianness) 🔵 High-Yield · common PYQ background

For the 32-bit value 0x12345678 stored at address 100: big-endian keeps the most significant byte first (100: 12, 101: 34, 102: 56, 103: 78); little-endian keeps the least significant byte first (100: 78, 101: 56, 102: 34, 103: 12). It matters when data is shared between machines or read byte by byte.

3. Design of the Arithmetic Logic Unit (ALU)

The circuit that actually computes — adders, multipliers, and the tricks that make them fast.

Adders: the building block 🟢 Core

Ripple Carry Adder (RCA)
n 1-bit full adders chained; carry "ripples" from LSB to MSB. Simple, but slow — the MSB must wait for every earlier carry.
Delay = n × Δ (Δ = delay of 1 full adder).
Carry Look-Ahead Adder (CLA)
Computes all carries in parallel using extra gates (generate/propagate logic), so it doesn't wait for ripples. Faster but more hardware.
Worked numerical (classic GATE pattern)
Q: A 16-bit adder is built from 4-bit carry-look-ahead adder (CLA) blocks connected by ripple carry between blocks. Each 4-bit CLA block has delay 10 ns to produce its sum and its carry-out. Find the total worst-case delay.
A: There are 16/4 = 4 blocks. Block 1 finishes in 10 ns and passes its carry-out to block 2, which then takes another 10 ns, and so on. Total delay = 4 × 10 = 40 ns. (Contrast: if all 4 blocks used full look-ahead across blocks too, delay would be much closer to a single block's 10 ns.)

Multiplication: Booth's Algorithm 🟢 Core

Booth's algorithm multiplies signed 2's-complement numbers by scanning pairs of bits of the multiplier and deciding to add, subtract, or do nothing to a running partial product, then arithmetic-shift right.

Rule, looking at multiplier bit Q₀ and the bit just shifted out Q₋₁:
Q₀ Q₋₁Action
0 0no operation, just shift
0 1Add multiplicand, then shift
1 0Subtract multiplicand, then shift
1 1no operation, just shift
Worked numerical
Q: Multiply 3 × (−4) using Booth's algorithm (4-bit).
A: Multiplicand M = 3 = 0011, Multiplier Q = −4 = 1100, Q₋₁ = 0, AC = 0000. Each step: check Q₀Q₋₁, do the add/sub, then arithmetic-shift AC:Q:Q₋₁ right by 1. 
Step  Q0Q-1  Action     AC after action   AC:Q:Q-1 after shift
1      0 0   none       0000              AC=0000 Q=0110 Q-1=0
2      0 0   none       0000              AC=0000 Q=0011 Q-1=0
3      1 0   AC=AC-M    1101              AC=1110 Q=1001 Q-1=1
4      1 1   none       1110              AC=1111 Q=0100 Q-1=1
Final product = AC:Q = 1111 0100 (8-bit 2's complement) = −12 — matching 3 × (−4). ✔
Why Booth's matters
It handles negative multipliers automatically and can skip strings of 0s or 1s, making multiplication faster than naive shift-and-add. GATE frequently gives you a partial trace and asks you to fill in the next AC or Q value — memorize the 4-row table above cold.

Division 🔵 High-Yield · ALU background

Two standard hardware algorithms, both repeat "shift, subtract divisor, check sign, restore if needed":

Restoring division
Subtract divisor; if remainder goes negative, add divisor back (restore) and quotient bit = 0. Else quotient bit = 1. Simple but the extra "restore" step costs time.
Non-restoring division
Never restores — instead alternates add/subtract based on the sign of the previous remainder. Same number of steps, no wasted restore cycle, so it's faster.

Carry look-ahead equations 🟢 Core

For each bit position define generate Gᵢ = Aᵢ·Bᵢ (this bit makes a carry by itself) and propagate Pᵢ = Aᵢ ⊕ Bᵢ (this bit passes an incoming carry on). Then Cᵢ₊₁ = Gᵢ + Pᵢ·Cᵢ and Sumᵢ = Pᵢ ⊕ Cᵢ. Expanding the recurrence removes the wait for ripples: C₁ = G₀ + P₀C₀, C₂ = G₁ + P₁G₀ + P₁P₀C₀, and so on. Each carry is a two-level AND-OR of G, P and C₀, so its delay does not grow with the bit position (but the gate fan-in does, which is why large adders use 4-bit blocks).

4. Design of the Control Unit

The part of the CPU that generates the timing/control signals telling every other block what to do, and when.

The instruction cycle in micro-operations 🟢 Core

Every instruction is really a short sequence of register transfers. GATE loves writing these out; you should be able to read/write them fluently.

Example — the Fetch cycle (same for every instruction): 
MAR ← PC
MBR ← Memory[MAR] , PC ← PC + 1
IR  ← MBR
Then Decode reads the opcode in IR, and Execute runs instruction-specific micro-ops, e.g. for ADD R1, [500]: 
MAR ← 500
MBR ← Memory[MAR]
R1  ← R1 + MBR

Two ways to build the control unit 🟢 Core

HardwiredMicroprogrammed
How signals are generatedFixed combinational logic / FSM built from gatesA tiny stored "control program" (microprogram) in a Control Store (ROM)
SpeedFast — pure logic delaySlower — an extra memory read per micro-instruction
FlexibilityHard to change — needs a re-design/re-wiringEasy to change — just rewrite the control store contents
Best forRISC, simple instruction sets, speed-critical CPUsCISC, complex/large instruction sets
Cost / complexityComplex to design, cheap to runSimple, systematic design; needs control-store memory

Microinstruction format

Each word in the control store is a microinstruction: a row of control-signal bits plus the address of the next microinstruction.

Control field
which signals to assert (e.g. MAR-load, ALU-add, Mem-read)
Address field
address of next micro-instruction
Horizontal microprogramming
One bit per control signal — wide word, no decoding needed, but uses lots of control-store space. Faster (parallel signals).
Vertical microprogramming
Signals are encoded (like a mini opcode) — narrow word, needs a decoder, saves space but slightly slower.
Worked numerical
Q: A control store must hold 256 microinstructions, each needing to specify one of 8 possible micro-operations per field, using vertical microprogramming with 3 independent fields. How many bits per microinstruction (ignoring the next-address field)?
A: Each field encodes 8 choices → needs log₂8 = 3 bits. With 3 independent fields → 3 × 3 = 9 bits for control, plus log₂256 = 8 bits for the next-address field → total 17 bits/microinstruction.
GATE angle to remember
Questions often give you total control store size and ask for the number of address bits (log₂ of total microinstructions), or give you the number of control signals and ask you to compare horizontal (1 bit/signal) vs vertical (encoded, fewer bits) word width.

Data path: single-bus vs three-bus 🟢 Core

In a single-bus data path only one register can drive the bus at a time, so the ALU needs a holding register Y for one operand and an output register Z for the result. In a three-bus data path two buses feed the ALU and the third carries the result back, so an ALU operation takes one step.

Worked example — R3 ← R1 + R2
Single bus (3 control steps):
  1. R1out, Yin
  2. R2out, Add (ALU uses Y and the bus), Zin
  3. Zout, R3in
Three bus (1 step): R1 → bus A, R2 → bus B, ALU result → bus C → R3
The instruction fetch on a single bus also takes 3 steps: (1) PCout, MARin, Read, Select4, Add, Zin; (2) Zout, PCin, Yin, wait for memory; (3) MDRout, IRin. More buses mean fewer steps per instruction but more hardware.

5. Memory Hierarchy & Cache Mapping

Why caches exist, how an address is split to find data in one, and the arithmetic GATE always asks.

The hierarchy 🟢 Core

Registers (fastest, smallest)
→
Cache (L1/L2/L3)
→
Main Memory (RAM)
→
Secondary storage (slowest, biggest)

The idea: keep frequently-used data in the fast, small, expensive memory close to the CPU (locality of reference), and fall back to slower memory only on a miss.

Average Memory Access Time (AMAT) 🟢 Core · memory hierarchy performance

AMAT = Hit time + Miss rate × Miss penalty
Or in terms of hit ratio h: Effective Access Time = h × Tc + (1 − h) × (Tc + Tm), where Tc = cache access time, Tm = main memory access time.
Worked numerical
Q: Cache access time = 10 ns, main memory access time = 100 ns, hit ratio = 0.9. Find effective access time.
A: EAT = 0.9×10 + 0.1×(10+100) = 9 + 11 = 20 ns.

How an address maps into cache — 3 schemes 🟢 Core · cache memory mapping

Every physical address is split into three fields: Tag | Set/Line index | Block offset. The scheme decides how many places one memory block can go.

Worked numerical (very common GATE pattern)
Q: Main memory = 4 GB (32-bit address), cache = 64 KB, block size = 32 bytes, direct-mapped. Find tag, index, and offset bit widths.
A:
Offset bits = log₂(block size) = log₂32 = 5 bits
Number of cache lines = cache size / block size = 65536/32 = 2048 lines → index bits = log₂2048 = 11 bits
Tag bits = total address bits − index − offset = 32 − 11 − 5 = 16 bits
Worked numerical — 4-way set associative
Q: Same cache (64 KB, 32-byte blocks) but organized as 4-way set-associative. Find the index bits.
A: Number of sets = lines / ways = 2048 / 4 = 512 sets → index bits = log₂512 = 9 bits. Tag bits become 32 − 9 − 5 = 18 bits (bigger tag because fewer sets to search).
Replacement & write policy — quick recall
When a set is full, a block must be evicted: LRU (least recently used) is the GATE favorite, also FIFO / random. Write policy: write-through (update memory immediately, simple, slower) vs write-back (update memory only on eviction, needs a "dirty bit", faster).

Write misses and cache miss types 🟢 Core

Policy pairOn a write hitOn a write miss
Write-through + no-write-allocateUpdate cache and memoryWrite memory only; the block is not brought into the cache
Write-back + write-allocateUpdate the cache and set the dirty bitFetch the block into the cache, then write it there

A write-back cache writes memory only when a dirty block is evicted, which saves bus traffic, but a replacement may then cost an extra memory write. Miss types (the 3 Cs): compulsory (first access to a block), capacity (the working set exceeds the cache) and conflict (too many blocks map to the same set; a fully associative cache has none).

Multi-level cache access time 🟢 Core · memory hierarchy performance

AMAT = t₁ + m₁·(t₂ + m₂·t_mem) where mᵢ is the miss rate of level i (local miss rate) and tᵢ its access time.

Worked numerical
Q: L1: 1 ns, miss rate 10%. L2: 10 ns, local miss rate 20%. Memory: 100 ns. Find the average access time.
A: AMAT = 1 + 0.1 × (10 + 0.2 × 100) = 1 + 0.1 × 30 = 4 ns.

Memory interleaving and memory types 🔵 High-Yield · supports memory interfacing

With m-way low-order interleaving, consecutive addresses fall in different banks (bank = address mod m), so m accesses can overlap. Example: 4 banks, 100 ns per bank access: fetching 8 consecutive words takes 2 × 100 = 200 ns (two rounds of 4 parallel accesses), against 800 ns from a single bank, assuming no bank conflicts.

Memory interfacing — chips, decoding & expansion 🟢 Core · named in the 2027 syllabus

Revision block for the 2027 syllabus line “memory interfacing and hierarchy”. Everything here is one idea: a big memory is an array of small chips, and the address bits decide which chip answers.

1. A memory chip, as the CPU sees it

A chip of N × w (N words, w bits per word) has log₂N address lines, w data lines, a chip select (CS) and read/write controls (RD/WR or OE/WE). CS is usually active-low: with CS inactive the chip ignores the address and its data lines float (tri-state), so many chips can share one data bus.

ChipAddress linesData linesCapacity
1K × 81081 KB
16K × 11412 KB
4M × 82284 MB

DRAM chips usually multiplex the address: the row and column halves arrive on the same pins one after the other (RAS then CAS), so address pins are about half of log₂N. Check whether a question asks for “address lines needed” (log₂N) or “address pins on a DRAM package”.

2. Address decoding & chip select

CPU address A(k−1) … A(m) (high bits)
→
Decoder
→
CS of one chip / chip group
CPU address A(m−1) … A0 (low bits)
→
Address pins of every chip in parallel
Rule. Low bits (as many as the chip has address lines) go to all chips and pick the word inside a chip. High bits go to a decoder (or logic) that raises exactly one CS and picks which chip. The decoder is enabled only for the address bits that must have a fixed value.
Trap — partial decoding
If some high address bits are not used in the decoder, they become don’t-cares and the same chip answers at several address ranges (aliasing / “mirroring”). Full decoding uses every high bit and gives a unique address for every location.

4. Representative problems

Problem 1 — expansion in both directions
Q: Build a 4K × 16 memory from 1K × 4 chips. How many chips, how are they arranged, and how are the address bits used?
A: Chips = (4096 × 16)/(1024 × 4) = 16. Columns = 16/4 = 4 chips side by side give the 16-bit word; rows = 4096/1024 = 4 groups give the depth. The 12-bit address splits as: A9–A0 (10 bits) to every chip; A11–A10 (2 bits) to a 2-to-4 decoder whose four outputs are the CS of the four rows.
Problem 2 — address ranges from a decoder
Q: A CPU has a 16-bit address bus. Four 2K × 8 chips are placed contiguously from 0000H, with A15–A13 required to be 000. Give each chip’s range.
A: Each chip has 11 address lines (A10–A0) and covers 800H bytes. A15–A13 = 000 enables a 2-to-4 decoder on A12, A11: 
Chip 0 (A12A11 = 00): 0000H – 07FFH
Chip 1 (A12A11 = 01): 0800H – 0FFFH
Chip 2 (A12A11 = 10): 1000H – 17FFH
Chip 3 (A12A11 = 11): 1800H – 1FFFH       total 8 KB
Because A15–A13 are decoded, the chips do not alias elsewhere in the 64 KB space. If A15–A13 were ignored, the same 8 KB would repeat 8 times (partial decoding).
Problem 3 — decoder sizing
Q: A 16-bit address bus drives 64 KB of memory made of 8K × 8 chips. How many chips and which decoder?
A: Chips = 64K/8K = 8 (all in one column, as the word is already 8 bits). Each chip needs 13 address lines (A12–A0); the remaining 3 bits A15–A13 feed a 3-to-8 decoder whose 8 outputs are the CS lines. Chip i occupies i × 2000H to i × 2000H + 1FFFH.
Byte-addressable memory on a wider bus
On a byte-addressable machine with a 32-bit data bus, the memory is built as 4 byte-wide banks. The 2 lowest address bits (A1–A0) choose the byte within the word and are not sent to the chips; the chips see A(k−1)–A2. Read the question to see whether the “word” is the byte or the bus width.

Virtual memory and the TLB 🔵 High-Yield · also covered in OS

A virtual address splits into page number | offset. The page table maps page → frame. Page-table size = (number of virtual pages) × (entry size): a 32-bit virtual address with 4 KB pages has 2²⁰ pages, so with 4-byte entries the table is 2²⁰ × 4 B = 4 MB. A TLB caches recent translations so most accesses skip the page-table lookup in memory. With a single-level page table:

Worked numerical
Q: TLB access 10 ns, memory access 100 ns, TLB hit ratio 90%. Find the effective access time.
A: A hit costs 10 + 100 = 110 ns. A miss costs 10 + 100 (page-table read) + 100 (data) = 210 ns. EMAT = 0.9 × 110 + 0.1 × 210 = 99 + 21 = 120 ns.

Secondary storage — disk access time 🟡 Extension · not named in 2027

Access time = seek time + rotational latency + transfer time. Average rotational latency is half a rotation; transfer time = (bytes wanted / bytes per track) × rotation time.

Worked numerical
Q: Seek time 4 ms, 7200 rpm, 400 sectors per track. Find the time to read one sector.
A: One rotation = 60/7200 s = 8.33 ms, so the average latency is 4.17 ms and one sector passes under the head in 8.33/400 = 0.021 ms. Total = 4 + 4.17 + 0.02 ≈ 8.19 ms.

6. I/O Interface: Interrupts & DMA

Three ways the CPU can move data in/out — and why DMA exists.
Programmed I/O
CPU repeatedly polls the device's status flag in a busy-wait loop. Simple, but wastes CPU cycles.
Interrupt-driven I/O
CPU carries on with other work; the device raises an interrupt signal only when it's ready. CPU saves state, runs the ISR (interrupt service routine), then resumes. Saves CPU time vs polling, but each transfer still passes through the CPU register-by-register.
DMA (Direct Memory Access)
A separate DMA controller moves an entire block directly between device and memory, without the CPU touching each word. CPU just sets up (starting address, count, direction) then is interrupted once at the very end. Best for bulk transfers (disk, network).

Cycle stealing

While a DMA transfer is in progress, the DMA controller "steals" memory bus cycles from the CPU one at a time, so both can (almost) work concurrently — this is why DMA is much more efficient than interrupt-driven I/O for large transfers.

Worked numerical
Q: A device transfers data at 1 MB/s. Each interrupt-driven transfer moves 4 bytes and costs the CPU 100 cycles of overhead (context switch + ISR) at 1 GHz. Compare CPU overhead per second against a DMA scheme that interrupts only once per 4 KB block.
A:
Interrupt-driven: transfers/sec = 1,000,000/4 = 250,000 interrupts/sec → overhead = 250,000 × 100 cycles = 25,000,000 cycles/sec = 2.5% of a 1 GHz CPU just on overhead.
DMA: interrupts/sec = 1,000,000/4096 ≈ 244 → overhead ≈ 24,400 cycles/sec — roughly 1000× less CPU overhead.
GATE angle
Typical questions: given interrupt latency & instruction execution time, compute total time lost to interrupts; or compare polling vs interrupt vs DMA overhead like above. Also know: vectored interrupts (device ID tells CPU where its ISR is) vs non-vectored (fixed single ISR address, must poll to find the source).

Interrupt priority: daisy chain and nesting 🟢 Core

When several devices share one interrupt line, the CPU needs a priority scheme. Daisy chain: the interrupt-acknowledge signal passes serially from device to device, so the device nearest the CPU has the highest priority. Parallel priority uses a separate request line per device, a mask register and a priority encoder; it is faster but needs more hardware. With nested interrupts a higher-priority request can interrupt a running ISR while lower-priority ones stay masked. The CPU finishes the current instruction before it responds to an interrupt.

Worked numerical
Q: A device transfers 4 MB/s in 4-byte words using cycle stealing. Each stolen memory cycle lasts 100 ns. What fraction of the memory bus time does DMA use?
A: 4 MB/s ÷ 4 B = 1 million words per second. Each steals 100 ns: 10⁶ × 100 ns = 0.1 s per second = 10% of the bus time, so the CPU keeps the other 90%.

7. Instruction Pipelining & Hazards

Overlap the execution of multiple instructions like an assembly line — the highest-yield COA topic after addressing modes.

The classic 5-stage pipeline 🟢 Core

IF Instruction Fetch → ID Instruction Decode → EX Execute → MEM Memory access → WB Write back
Cycle →123456
Instr 1IFIDEXMEMWB
Instr 2IFIDEXMEMWB

Without pipelining each instruction takes 5 cycles start-to-finish; with pipelining, once the pipe is full, one instruction completes every cycle.

Speedup formula

Time (non-pipelined) = n × k
Time (pipelined)      = k + (n − 1)
Speedup = (n × k) / (k + n − 1)
n = number of instructions, k = number of pipeline stages. As n→∞, speedup → k.
Worked numerical
Q: A 5-stage pipeline, clock cycle = 2 ns, runs 100 instructions with no stalls. Find total time and speedup vs non-pipelined execution.
A: Pipelined cycles = k + n − 1 = 5 + 99 = 104 → time = 104 × 2 = 208 ns.
Non-pipelined time = n × k × cycle = 100 × 5 × 2 = 1000 ns.
Speedup = 1000 / 208 ≈ 4.8× (close to the ideal max of 5).

Hazards — the reason pipelines stall 🟢 Core

HazardCauseFix
StructuralTwo instructions need the same hardware resource (e.g. one memory port for both instruction fetch and data access) at onceDuplicate hardware (separate I-cache/D-cache), or stall
DataAn instruction needs a result that a previous, still-unfinished instruction hasn't produced yetForwarding/bypassing (feed result directly from EX/MEM stage), or stall
Control (branch)The next instruction to fetch isn't known until a branch is resolved (usually in EX/MEM stage)Branch prediction, delayed branch, or stall until resolved
Worked numerical — data hazard with stalls
Q: ADD R1, R2, R3 is immediately followed by SUB R4, R1, R5 in a 5-stage pipeline with no forwarding. R1 is written in WB (cycle 5 of instr 1) but needed by SUB's EX stage. How many stall (bubble) cycles are needed?
A: Without forwarding, SUB's ID stage (where operands are read) must happen no earlier than the cycle right after instr 1's WB. Instr 1: IF ID EX MEM WB (cycles 1-5). Instr 2 naturally would be ID at cycle 3 — but it needs the value only ready after cycle 5. So ID must be delayed to cycle 6 → 3 stall cycles inserted. (With full forwarding from EX/MEM to the next instruction's EX, this typically drops to 0–1 stalls.)
GATE angle
Questions typically give a sequence of dependent instructions and a pipeline diagram, then ask: total cycles with stalls, or how many bubbles a specific forwarding path removes, or the effect of a branch misprediction (stall cycles = number of stages before branch resolves).

Data hazard types: RAW, WAR, WAW 🟢 Core

HazardMeaningOccurs in a simple in-order 5-stage pipeline?
RAW (true dependency)A later instruction reads a register before an earlier one has written itYes — the main cause of stalls
WAR (anti-dependency)A later instruction writes a register before an earlier one has read itNo — reads happen early, writes late
WAW (output dependency)Two instructions write the same register; the writes could complete out of orderNo — writes stay in order

WAR and WAW appear with out-of-order execution or instructions of different latency, and are removed by register renaming. With forwarding, an ALU result flows from EX/MEM straight into the next instruction's EX stage, removing the stall for back-to-back ALU instructions. A load followed by a use of the loaded value still costs 1 stall cycle even with forwarding, because the data is only available after MEM.

Branch penalty and prediction 🟢 Core

CPI = 1 + (branch frequency) × (fraction mispredicted or stalled) × (penalty in cycles). With 20% branches and a 3-cycle penalty, always stalling gives CPI = 1 + 0.2 × 3 = 1.6; with a predictor that is wrong 40% of the time, CPI = 1 + 0.2 × 0.4 × 3 = 1.24. Techniques: static prediction (always not-taken, or backward-taken/forward-not-taken), delayed branch (the instruction in the delay slot always executes), and dynamic prediction with a branch history table. A 2-bit saturating counter needs two wrong predictions in a row to change its mind, so a loop branch mispredicts only once per loop exit.

Pipeline with unequal stages 🟢 Core

The clock must fit the slowest stage plus the latch delay. A non-pipelined machine takes the sum of the stage delays per instruction.

Worked numerical
Q: Four stages take 5, 10, 8 and 7 ns, and each pipeline latch adds 1 ns. Find the speedup for 100 instructions.
A: Clock = 10 + 1 = 11 ns. Pipelined time = (4 + 99) × 11 = 1133 ns. Non-pipelined time = (5 + 10 + 8 + 7) × 100 = 3000 ns. Speedup = 3000 / 1133 ≈ 2.65, far below 4 because the slow stage sets the clock for everyone.

CPU performance: CPI, MIPS and Amdahl's law 🔵 High-Yield · performance questions

CPU time = instruction count × CPI × clock cycle time; MIPS = clock rate / (CPI × 10⁶). For a mix, CPI is the frequency-weighted average of the per-class cycle counts. Amdahl's law: if a fraction f of the time is sped up by a factor s, Speedup = 1 / ((1 − f) + f/s), and the limit as s → ∞ is 1/(1 − f).

Worked numerical
Q: A 1 GHz CPU runs a mix of 50% ALU (1 cycle), 20% loads (2), 10% stores (2) and 20% branches (3). Find CPI, MIPS and the time for 10⁹ instructions. Separately, if 80% of a program is sped up 4×, what is the overall speedup?
A: CPI = 0.5·1 + 0.2·2 + 0.1·2 + 0.2·3 = 0.5 + 0.4 + 0.2 + 0.6 = 1.7. MIPS = 1000 / 1.7 ≈ 588. Time = 10⁹ × 1.7 × 1 ns = 1.7 s. Amdahl: 1 / (0.2 + 0.8/4) = 1 / 0.4 = 2.5, and even an infinite speedup of that part could give at most 1/0.2 = 5.

Q16 · Expanding opcode — how many zero-address instructions?
A 16-bit instruction has operand fields of 4 bits each. The design must provide 15 three-address instructions, 14 two-address instructions and 31 one-address instructions, and all remaining opcode space is used for zero-address instructions. What is the maximum number of zero-address instructions?
  1. 15
  2. 32
  3. 16
  4. 31
Idea: use some bit patterns of a short opcode as 'escape codes' that extend the opcode into the bits of an unused operand field.

Level 1 — three-address (4-bit opcode + 3 operands of 4 bits = 16 bits):
    16 opcode patterns, 15 used  →  1 pattern left as an escape.
Level 2 — two-address (the escape + the 4 bits of the third operand field become opcode = 8 bits, 2 operands):
    1 × 16 = 16 patterns, 14 used  →  2 left.
Level 3 — one-address (12-bit opcode, 1 operand):
    2 × 16 = 32 patterns, 31 used  →  1 left.
Level 4 — zero-address (the full 16 bits are opcode):
    1 × 16 = 16 instructions.

Formula for the number of patterns available at the next level:  (patterns left) × 2^(operand field width).
Check: the level-by-level counts (1 → 2 → 1 → 16) were reproduced by program.
Trap: do not stop after level 3 — each unused pattern multiplies by 16 once more when the last operand field is absorbed.

Correct: Option 3 — at most 16 zero-address instructions.

Q17 · TLB organisation — tag bits and storage
A system has 32-bit virtual addresses, 36-bit physical addresses and 4 KB pages. Its TLB has 64 entries and is 4-way set associative; each entry stores the tag, the physical frame number and one valid bit. How many tag bits does the TLB use and how many bits of storage does it need?
  1. 16 bits and 2624 bits
  2. 20 bits and 2880 bits
  3. 16 bits and 2688 bits
  4. 12 bits and 2368 bits
Page size 4 KB  →  offset = 12 bits.
Virtual page number (VPN) = 32 − 12 = 20 bits.     Physical frame number (PFN) = 36 − 12 = 24 bits.

TLB: 64 entries, 4-way  →  64 / 4 = 16 sets  →  index = log2 16 = 4 bits.
Tag = VPN − index = 20 − 4 = 16 bits.

Bits per entry = tag 16 + PFN 24 + valid 1 = 41.
Total storage = 64 × 41 = 2624 bits (= 328 bytes).

Comparison: fully associative → tag = 20 bits, entry = 45 bits, total = 2880 bits (no index bits, but 64 comparators);
direct mapped → 6 index bits, tag = 14 bits.
Check: all of these were recomputed by program. A single-level page table for the same address space would need 2^20 × 4 B = 4 MB per process,
which is why a small TLB in front of it pays off.
Trap: the TLB index uses bits of the VPN (the page number), never the offset bits.

Correct: Option 1 — 16 tag bits and 2624 bits of storage.

Q18 · Amdahl's law — speedup, limit and required parallel fraction
80% of a program's execution time can be perfectly parallelised and the other 20% is strictly sequential. What are (i) the speedup on 8 processors, (ii) the maximum possible speedup on any number of processors, and (iii) the parallel fraction needed to get a speedup of 4 on 8 processors?
  1. 3.33, 5 and 85.7%
  2. 4.0, 5 and 75%
  3. 3.33, 8 and 85.7%
  4. 3.33, 5 and 95%
Amdahl's law:  Speedup = 1 / [ (1 − p) + p / n ]      (p = parallelisable fraction, n = processors)

(i)   p = 0.8, n = 8:   1 / (0.2 + 0.8/8) = 1 / (0.2 + 0.1) = 1 / 0.3 = 3.33
(ii)  n → ∞:            1 / (1 − p) = 1 / 0.2 = 5     — the sequential 20% caps the speedup however many processors are added
(iii) 4 = 1 / [ (1 − p) + p/8 ]   →   (1 − p) + p/8 = 0.25   →   1 − (7/8)p = 0.25   →   p = 0.75 / (7/8) = 6/7 ≈ 85.7%

Check: exact fractions give 10/3, 5 and 6/7. Even with 16 processors the speedup is only 1 / (0.2 + 0.05) = 4.
Trap: speedup is NOT 0.8 × 8 + 0.2; the sequential part does not shrink, so the denominator is the new TIME, not a throughput sum.

Correct: Option 1 — 3.33, 5 and about 85.7%.

Q19 · Disk access time — random block versus long contiguous read
A disk spins at 7200 rpm, has an average seek time of 8 ms and 400 sectors of 512 bytes per track. How long does it take to read (i) a 4 KB block stored in 8 consecutive sectors at a random place and (ii) a 1 MB file stored in consecutive sectors (assume no extra seek or track-switch time)?
  1. 12.33 ms and 54.83 ms
  2. 16.5 ms and 58.9 ms
  3. 12.33 ms and 4.17 ms
  4. 8.17 ms and 50.7 ms
One revolution = 60 / 7200 s = 8.333 ms.        Average rotational latency = half a revolution = 4.167 ms.
Transfer time per sector = 8.333 ms / 400 = 0.020833 ms  (a full track is read in one revolution).

(i)  4 KB = 8 sectors:   seek 8 + rotation 4.167 + transfer 8 × 0.020833 (= 0.167)  =  12.33 ms
(ii) 1 MB = 2048 sectors: seek 8 + rotation 4.167 + transfer 2048 × 0.020833 (= 42.67)  =  54.83 ms

Disk access time = seek + rotational latency + transfer time.
Sustained transfer rate on a track = 400 × 512 B per 8.333 ms = 204,800 B / 8.333 ms ≈ 24.6 MB/s (10^6 bytes).
Check: all quantities were recomputed with exact fractions.
Lesson: for a small block seek + rotation (12.17 ms) dominates, while for a large contiguous file transfer (42.67 ms) dominates — which is why layout matters.

Correct: Option 1 — 12.33 ms for the random 4 KB read and 54.83 ms for the 1 MB contiguous read.
